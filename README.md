# 光纤宽带新装工单系统

零第三方依赖（仅 Python 3 标准库 + 原生 JS）的宽带新装全流程系统：
受理 → 地址核查 → 端口预占 → 排期 → 上门勘线 → 设备绑定 → 测速 → 用户签收开通。

## 一条本地启动命令

```bash
./run.sh          # 默认 8000 端口
./run.sh 9000     # 指定端口
```

启动后：

| 端 | 地址 | 可见内容 |
|---|---|---|
| 安装端（受理员/工程师） | http://127.0.0.1:8000/installer | 资源地图、安装排程、现场勘线、设备绑定、测速与签收 |
| 用户端 | http://127.0.0.1:8000/user | 仅预约、测速、验收结果（凭短信验证码本人签收） |

等价手动命令：`python3 -m app.seed && python3 -m app.server`
重置演示数据：`python3 -m app.seed --reset`

## 端口不足样例

种子数据内置 **「阳光花园2栋」**：唯一分光器 SP-2-01 的 4 个端口全部 `confirmed`。

- 资源地图中该楼栋显示红色 **「端口已满」** 统计条；
- 工单 **BB-SEED-PORTFULL** 即为对该楼栋的申请，状态 `rejected（端口已满）`；
- 在「新装受理」再对「阳光花园2栋」提交一单，受理核查后直接 `rejected`，可在工单详情里等待扩容后「重新核查端口」。

其他演示工单：`BB-SEED-SCHED`（已排期待上门）、`BB-SEED-WAIT`（测速达标待用户签收，
用户端输入该单号可直接体验签收，验证码见页面提示）、`BB-SEED-STALE`（预占超时，打开资源地图即自动释放）。

## 业务规则（状态机）

```
draft ──地址不匹配──▶ address_error ──更正地址──▶ reserved
  │
  ├──端口满──▶ rejected ──(扩容后重新核查)──▶ reserved
  └──有端口──▶ reserved ──排期──▶ scheduled ──上门用户不在──▶ user_absent ──改期──▶ rescheduled
                                   │                                      │
                                   └──────────┐  ◀───────────────────────┘
                                              ▼
                                        现场勘线（记录光纤路径/分光器端口/光功率/照片）
                                       ┌──────┴───────┐
                              光功率不达标            合格：reserved 端口原子确认 confirmed
                              optical_failed                 │
                              （整改复测）                    ▼
                                                        surveyed ◀── 换绑设备/复测仍回到此
                                                       ┌───┴───┐
                                              测速不达标      达标
                                              speed_failed    │
                                              （整改复测）     ▼
                                                   用户本人验证码签收 → activated
```

- **一户一端口**：`UPDATE ... WHERE status='free'` 原子抢占 + 进程锁，并发申请只有一户成功；
  已 `confirmed` 端口后到申请永不可占用，勘线时也只能确认本工单预占的端口。
- **预占超时自动释放**：预占 30 分钟未排期，端口回 `free`、工单转 `expired`
  （环境变量 `BB_RESERVE_TIMEOUT` 可调，单位秒）；已排期/改期/用户不在的端口不因计时释放。
- **工程师不能代签**：`actor=engineer` 一律拒绝；需模拟短信中的 6 位验证码。
- **不达标不开通**：光功率超出 [-27, -8] dBm 区间停在 `optical_failed`；
  测速下行低于签约带宽 90% 停在 `speed_failed`；两种状态签收接口均拒绝。
- **设备换绑**：旧机回库 `stock`、新机 `bound` 在一个事务内完成，并发换绑同一台设备只有一单成功。

## 异常处理对照

| 场景 | 入口 | 系统行为 |
|---|---|---|
| 端口已满 | 受理核查 / 更正地址 | 工单 `rejected`，不预占任何端口，可扩容后重新核查 |
| 地址写错 | 受理核查 | 工单 `address_error`，受理员更正后重新核查资源 |
| 用户不在 | 排程看板/工单详情 | 工单 `user_absent`，短信通知，端口保留，改期后继续 |
| 光功率不达标 | 现场勘线 | 读数与阈值同时红字显示，工单 `optical_failed`，整改复测 |
| 设备更换 | 工单详情-设备绑定 | 旧设备回库、新设备占用，记录换绑日志 |
| 预约改期 | 排程看板/工单详情 | 短信通知，预占计时刷新，可再次上门 |

## 模拟适配器与本地存储

- 测速适配器：`app/adapters.py`，按签约带宽计算，可「模拟线路异常」稳定产生不达标读数；
- 短信适配器：通知只写入 SQLite `sms_log` 表（工单详情可见），不真实外发；
- 现场照片：multipart 上传，落盘到 `data/photos/order_<工单号>/`，由 `/photos/` 只读托管（含路径穿越防护）；
- 数据库：`data/broadband.db`（SQLite，WAL 模式）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

21 个用例，重点覆盖需求点名的四项：

- **端口竞争**：20 线程同时申请单端口楼栋，仅 1 户 `reserved`，其余 19 户 `rejected`；
  后来者不能在勘线时占用他人 `confirmed` 端口；
- **超时释放**：预占过期后端口自动回池、工单 `expired`、新单可顶上；已排期不释放；
- **设备换绑**：旧机回库新机占用，两单并发换绑同一台设备只有一单成功；
- **签收权限**：工程师代签拒绝、错误验证码拒绝、测速不达标拒绝，用户本人正确签收才 `activated`；
- 另含地址错误更正、光功率不达标阻断、用户不在改期、照片落盘与 HTTP 全流程冒烟。

## 目录结构

```
app/
  config.py     阈值（光功率/测速90%/预占超时）、状态常量、路径
  db.py         SQLite 连接（显式事务）与建表
  adapters.py   模拟测速仪、模拟短信
  services.py   工单状态机与全部业务规则
  seed.py       幂等种子数据（含全满楼端口不足样例）
  server.py     标准库 HTTP：REST API + 静态页 + 照片托管
web/
  installer.html / user.html / app.css / app.js
data/           运行期生成：broadband.db、photos/（已 gitignore）
tests/          test_workflow.py（业务）、test_api.py（HTTP）
run.sh          一条本地启动命令
```
